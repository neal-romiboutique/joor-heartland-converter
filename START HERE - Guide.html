Romi Boutique Order Converter JOOR & NuOrder → Heartland

Turns a wholesale order export into Heartland import files. Grids first, then the PO.

Setup

Do this once per Mac. No typing required.

OneUnzip and move the folder

Double-click the zip you were sent (it's in Downloads). A joor-heartland-converter folder appears. Drag that folder onto the Desktop and leave it there. Everything the converter needs is already inside it, including the Heartland connection details.

Don't delete or move anything out of the folder. Some files are hidden on purpose (their names start with a dot) — they're what connect the app to Heartland.

TwoOpen it the first time

Double-click Order Converter inside the folder. Because the file came from an email, the Mac will block it the first time with a message like “Apple could not verify…” or “…from an unidentified developer.” This is expected. To allow it:

  • Click Done (or OK) on the warning.
  • Open System Settings → Privacy & Security and scroll to the bottom. Next to the message about “Order Converter”, click Open Anyway, then confirm with your password or Touch ID.
  • Older Macs: instead, right-click Order Converter, choose Open, then Open again.

You only do this once. After that, a plain double-click works.

ThreeLet first-time setup finish

A Terminal window opens and sets itself up. Two things may happen, both only once:

  • A window offers to install “developer tools.” Click Install, agree, and wait (10–30 minutes). When it's done, double-click Order Converter again.
  • “Installing helper libraries…” appears for about a minute. Needs internet. Let it run.

Then a browser tab opens with the converter. That's it — you're set up.

FourEveryday use

Double-click Order Converter. A Terminal window opens and the browser tab follows a second later.

Leave the Terminal window open while you work. The browser tab is just the screen; the Terminal window is the engine. Close it and the converter stops.

FiveGetting updates later

Double-click Pull_Updates in the same folder, then close the converter's Terminal window and double-click Order Converter again. If it says it couldn't update, nothing is broken — ask Neal for the newest zip, then replace the old folder on the Desktop with the new one.

JOOR orders

Two passes over the same export file. Pass one, the grids import, is the required one — it creates the products in Heartland. Pass two, the PO import, is optional: it saves you from typing the purchase order in by hand, but you can always build the PO in Heartland yourself instead.

The grids import has to come first, and has to be finished. The PO file is built from Item #s that don't exist until the grids import generates them. Run the PO tab first and it either produces an empty file or warns that nothing matched.

Before you startExport from JOOR

  • Either JOOR format works — Basic Export (one row per size) or Order to Size (sizes across the top). Prefer Download Order Summary Excel: it carries real color names.
  • Don't open the export in Excel first. Excel quietly rewrites values on save — style numbers become floats, size tokens like 00-14 become dates.

Pass one · requiredJOOR Grids Import

Drag the export onto the drop area, click Convert. A file named …_GRIDS_IMPORT.xlsx lands in Downloads.

The dark log panel is the point of the screen — read it before importing anything. One line per grid:

  Jersey Deep V Tee / Burnt Fig: ordered ['S', 'M'] -> [letters]
  generated ['XS', 'S', 'M', 'L']  | price $145 (JOOR Sugg. Retail)
  • SKIP (already exists in Heartland) — that style/color is already in the system and was left out of the file on purpose.
  • WARNING: unrecognized size convention — the grid is still written, but with Generate Items = false. Heartland will create the grid empty and you add the sizes by hand.
  • NOTE: color … looks like a vendor code — you got C0308 instead of Cardinal Red. Re-download from JOOR using Order Summary Excel.

What the converter decides for you:

FieldRule
SizesFills out the store's base run around what was ordered — letters XS–L, even numeric 0–10, denim 24–29, euro 70–90, rings 6–8, or just OS. Ordering outside the base run extends the ladder rather than replacing it.
PriceJOOR's Sugg. Retail if present, otherwise 2.4 × cost. Always rounded up to a whole dollar.
ColorTitle case, with slashes turned into ampersands (BLUE/BLACK → Blue & Black). W/ is left alone — it means "with."
DescriptionTitle case, with the style number stripped off the front if the vendor prefixed it.
DuplicatesChecked live against Heartland on vendor + style number + color, in both the current and the older slash color format.

Optional, but worth doing now: open the downloaded file and fill the four dropdown columns — Shopify Category, Shopify Color, Category, Active fit guide. The import works fine without them; you'd just be filling them in grid by grid in Heartland later instead of once here. Everything else in the file is ready as-is.

Import at Inventory → Item Grids → Import. All columns auto-map by name; leave Generate Items = true alone, or Heartland rejects the file.

Check one grid before moving on. Open a grid Heartland just created and confirm the item count matches the number of sizes in the ladder. Doubled items mean something went wrong with Generate Items.

Pass two · optionalJOOR PO Import

Skip this if you'd rather build the PO in Heartland by hand. If you use it, run it only after the grids import has completed and the items exist in Heartland. Switch to the JOOR PO Import tab and drop the same export again — no items export needed, Item #s are looked up live from Heartland. You get …_PO_IMPORT.xlsx.

WARNING: N JOOR line(s) had no matching Heartland item. The vendor's items loaded fine, so those specific style/color/size combos simply aren't in Heartland yet. Fix the grids, then run this tab again — don't import a short PO.

Import at Purchasing → Purchase Orders → Import. Then, in Heartland:

  • The PO # column reads CHECK HEARTLAND HIGHEST PO# — a placeholder, because Heartland requires the field but won't auto-number on import. Look up the highest existing PO number and set it yourself.
  • The JOOR order number is in PO Description, so it stays searchable.
  • The PO arrives as Pending. Open it manually to finish.

NuOrder orders

Grids only. There's no NuOrder PO tab — once the grids are in Heartland, build the PO there by selecting them.

OneExport from NuOrder

Export the order as xlsx. The file needs the NuORDER Order Data tab — that's the sheet the converter reads. The Summary tab is ignored. Don't open it in Excel first.

TwoType the vendor name

NuOrder never puts the brand name in the file, so the Vendor box appears on this tab and has to be filled in before Convert unlocks.

It must match Heartland exactly. Check the spelling against Purchasing → Vendors first. A near-miss creates a duplicate vendor record.

ThreeConvert and check the log

  [nuorder] vendor='Mother'  38 ordered line(s);
  skipped 112 zero-qty size row(s)

The skipped rows are expected. NuOrder exports the vendor's entire size run whether or not you bought it, so anything with a blank Qty was offered, not ordered. If the skipped number looks far too high, confirm you exported the placed order and not a linesheet.

Reading the columns:

NuOrder columnBecomes
Qty × Units Per PackQuantity ordered — packs are multiplied out
Wholesale (USD)Default Cost
M.S.R.P (USD)Price, if present; otherwise 2.4 × cost, rounded up
NameDescription, with the style number stripped off the front

FourImport into Heartland

Same as JOOR: fill the four dropdown columns in the downloaded file, then Inventory → Item Grids → Import. Build the PO in Heartland afterwards.

If you drop the wrong file

A NuOrder file dropped on a JOOR tab stops with an error telling you to use the NuOrder tab. Nothing is written, so just switch tabs and try again.
